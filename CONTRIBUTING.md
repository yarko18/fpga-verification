# Contributing

Contributions are welcome.

## Contributor agreement

Every contributor must accept the applicable contributor agreement before a
pull request can be merged:

- individuals: [`CLA-INDIVIDUAL.md`](CLA-INDIVIDUAL.md);
- organizations and employer-owned contributions:
  [`CLA-CORPORATE.md`](CLA-CORPORATE.md).

An Authorized Contributor covered by a Corporate CLA must also accept the
Individual CLA unless the project maintainer expressly waives that requirement
in writing.

To accept the Individual CLA, email `yarko@proton.me` from your contact address
with the following statement and information:

```text
I accept the FPGA Verification Individual Contributor License Agreement,
version 1.0 dated 9 October 2026.

Full legal name:
GitHub or other contributor account:
Contact email:
Earlier contributions covered, if any:
Date:
```

To accept the Corporate CLA, an authorized signatory must email
`yarko@proton.me` with the following statement and information:

```text
[Legal name of Organization] accepts the FPGA Verification Corporate
Contributor License Agreement, version 1.0 dated 9 October 2026.

Jurisdiction and registration number:
Registered address:
Authorized signatory name and title:
Administrative contact:
Authorized Contributors:
Date:
```

CLA acceptance records are private and handled according to
[`PRIVACY-NOTICE.md`](PRIVACY-NOTICE.md). Do not put signatures, home
addresses, or other private CLA information in a public pull request.

## Pull request process

1. Fork the repository.
2. Create a branch for your changes.
3. Make your changes.
4. Run the tests.
5. Open a pull request.

Please keep pull requests focused on a single change and follow the existing code style.

If you are planning a larger change, consider opening an issue first.

## License-required contributions

A pull request submitted to satisfy the FPGA Verification Commercial
Reciprocity License 1.0 must also:

- identify the Software version and Covered Change;
- contain the complete non-secret Corresponding Source or an exact immutable
  link permitted by the license;
- include build, test, deployment, and self-hosting instructions where
  applicable;
- describe external dependencies and material runtime interactions; and
- identify only the general category of any Protected Information removed.

Never publish credentials, personal data, customer data, confidential product
information, confidential test vectors, or other Protected Information. Follow
the private security-disclosure procedure in the license when immediate
publication would disclose an unremediated vulnerability.

The contribution obligation is satisfied by submission of a complete and
compliant pull request; acceptance or merge is not guaranteed.
